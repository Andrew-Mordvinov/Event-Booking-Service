# Event Booking Service

Сервис бронирования мероприятий на .NET 10 + ASP.NET Core.

## Запуск

Запуск можно осуществить несколькими способами - через Visual Studio, консоль или подготовленный docker-compose.yml файл. Для редактирования нужна Visual Studio 2026 (не ниже). При запуске не через docker-compose по умолчанию приложения работают на портах 7100, 7200 и 7300 для https, 5100, 5200 и 5300 для http.

### Через Visual Studio 

Для запуска необходима среда исполнения для .NET 10, 3 базы данных Postgresql (проверялось на 18 версии, но возможна работа и на более низких версиях) и Kafka.

1. Клонируйте репозиторий:

`git clone https://github.com/Andrew-Mordvinov/Event-Booking-Service.git`

2. Перейдите в каталог `/EventBookingService` и настройте строки подключения в файлах appsettings.json (ConnectionStrings) в каждом проекте `Bookings/Presentation.Bookings`, `Events\Presentation.Events` и `Users\Presentation.Users`. Также настройте подключение к Kafka в разделе KafkaSettings для проектов Events и Bookings. Также можете изменить настройки JwtSettings для токена авторизации, но они должны быть аналогичными во всех трех проектах.

3. Убедитесь, что базы данных и Kafka работают и доступны.

4. В Visual Studio в меню "Отладка" найдите пункт "Запускаемый проект/профиль", в окне выберите опцию "Несколько запускаемых проектов" и настройте запуск всех трех проектов Presentaion и желаемый профиль (http/https). 

5. Убедитесь, что выбранный профиль сохранен и запустите решение по нему.

### Через командную строку

1. Клонируйте репозиторий:

`git clone https://github.com/Andrew-Mordvinov/Event-Booking-Service.git`

2. Перейдите в каталог `/EventBookingService` и настройте строки подключения в файлах appsettings.json (ConnectionStrings) в каждом проекте `Bookings/Presentation.Bookings`, `Events\Presentation.Events` и `Users\Presentation.Users`. Также настройте подключение к Kafka в разделе KafkaSettings для проектов Events и Bookings. Также можете изменить настройки JwtSettings для токена авторизации, но они должны быть аналогичными во всех трех проектах.

3. Убедитесь, что базы данных и Kafka работают и доступны.

4. В каталогах проектов Presentation выполните команду:

`dotnet run`

или с параметрами, чтобы явно выбрать профиль http/https:

`dotnet run --launch-profile https`

`dotnet run --launch-profile http`

### Через docker-compose.yml

1. Клонируйте репозиторий:

`git clone https://github.com/Andrew-Mordvinov/Event-Booking-Service.git`

2. В корне репозитория находится файл .env.example. Создайте файл .env в том же каталоге как его копию.

3. В файле-копии заполните параметры актуальными значениями. **Главное, обратите внимание на внешние порты баз данных и API**. Эти порты не должны быть заняты другими приложениями, остальное можно оставить по умолчанию.

4. В командной строке, находясь в каталоге с docker-compose.yml, выполните команду:

`docker-compose up -d --build`

5. Сборка образов приложений может занять время при первом запуске. В следующий раз можно не использовать флаг --build, если исходный код не менялся.

>**Обратите внимание**: в варианте с docker работает только вариант http и по умолчанию на портах 5001, 5002 и 5003

### Запуск тестов

Для запуска тестов можно предварительно выполнить следующую команду, находясь в каталоге с тестовым проектом:

`dotnet test`

>**Обратите внимание**: для запуска интеграционных тестов необходимо иметь установленный и запущенный Docker, так как используется пакет `Testcontainers.Postgresql`. Первый запуск тестов может быть длительным, так как потребуется загрузка образов.

## API Endpoints

### Управление мероприятиями

| Метод   | URL           |Авторизация| Описание                           |
|---------|---------------|-----------|------------------------------------|
| GET     | /events       | Да        |Возвращает список мероприятий с поддержкой фильтрации и пагинации.<br/><br/>**Параметры запроса:**<br/>- `title` (string, optional) – фильтр по названию мероприятия<br/>- `from` (datetime, optional) – фильтр по дате начала (>= from)<br/>- `to` (datetime, optional) – фильтр по дате окончания (<= to)<br/>- `page` (int, optional, default=1) – номер страницы<br/>- `pageSize` (int, optional, default=10) – размер страницы (от 1 до 100) |
| GET     | /events/{id}  | Да        | Возвращает мероприятие с указанным ID                              |
| POST    | /events       | Да (Админ)| Создает новое мероприятие. При успехе возвращает 201 Created       |
| PUT     | /events/{id}  | Да (Админ)| Полностью обновляет мероприятие с указанным ID                     |
| DELETE  | /events/{id}  | Да (Админ)| Удаляет мероприятие с указанным ID                                 |

### Управление бронированиями

| Метод   | URL            |Авторизация| Описание                               |
|---------|----------------|-----------|----------------------------------------|
| GET     | /bookings/{id} | Да        |Возвращает бронирование с указанным ID |
| DELETE  | /bookings/{id} | Да        |Отмена бронирования и возврат места    |
| POST    | /events/{id}/book | Да     |Создает бронирование на мероприятие. При успехе возвращает 202 Accepted со ссылкой на созданную бронь или 409 Conflict, если мест на мероприятие не осталось |

### Аутентификация и авторизация

| Метод   | URL            |Авторизация| Описание                               |
|---------|----------------|-----------|----------------------------------------|
| POST    | /auth/register | Нет       |Регистрация нового пользователя         |
| POST    | /auth/login    | Нет       |Авторизация пользователя и получение токена|

## Модели данных

### Event (Мероприятие)

| Поле          | Тип      | Описание                                           |
|---------------|----------|----------------------------------------------------|
| Id             | Guid     | Уникальный идентификатор мероприятия               |
| Title          | string   | Название мероприятия (обязательное поле)           |
| Description    | string   | Описание мероприятия (может быть пустым)           |
| StartAt        | DateTime | Дата и время начала мероприятия                    |
| EndAt          | DateTime | Дата и время окончания мероприятия                 |
| TotalSeats     | Int 		  | Общее число мест для мероприятия. Обязательно для заполнения                   |
| AvailableSeats | Int      | Число мест, доступных для бронировании.<br>При успешном бронировании уменьшается|

**Валидация:**
- `Title` не может быть пустым или состоять только из пробелов
- `StartAt` должна быть меньше или равна `EndAt`
- При создании через `TryCreate` выполняется дополнительная валидация обязательных полей

### Booking (Бронирование)

| Поле         | Тип               | Описание                                        |
|--------------|-------------------|--------------------------------------------|
| Id           | Guid              | Уникальный идентификатор бронирования      |
| EventId      | Guid              | Идентификатор мероприятия (внешний ключ)   |
| UserId       | Guid              | Идентификатор пользователя (внешний ключ)  |
| Status       | BookingStatus     | Статус обработки бронирования              |
| CreatedAt    | DateTime          | Дата и время создания бронирования         |
| ProcessedAt  | DateTime?         | Дата и время обработки бронирования (если выполнена) |

### BookingStatus (Статусы бронирования)

| Значение | Код  | Описание                                           |
|----------|------|----------------------------------------------------|
| Pending  | 0    | Ожидает обработки. Бронирование создано, но еще не обработано фоновым сервисом |
| Confirmed| 1    | Подтверждено. Бронирование успешно обработано      |
| Rejected | 2    | Отклонено. Бронирование не может быть выполнено    |
| Cancelled| 3    | Бронирование отменено пользователем или администратором    |

### User (Пользователь)

| Поле         | Тип               | Описание                                |
|--------------|-------------------|-----------------------------------------|
| Id           | Guid              | Уникальный идентификатор пользователя   |
| Login        | string            | Логин пользователя (уникальный)         |
| PasswordHash | string            | Хэш пароля                              |
| Role         | Roles             | Роль пользователя                       |

### Roles (Роли)

| Значение | Код  | Описание                                           |
|----------|------|----------------------------------------------------|
| User  | 0    | Обычный пользователь |
| Admin | 1    | Пользователь с административными правами      |

## Структура решения

Решение разделено на следующие элементы:
1. **Bookings** - в этой папке находятся проекты, относящиеся к сервису бронирования. Главный запускаемый проект - Presentation.Bookings.
  - **Application.Bookings** - слой приложения (use-cases для сущностей и интерфейсы портов)
  - **Domain.Bookings** - содержит ключевые сущности без внешних зависимостей.
  - **Infrastructure.Bookings** - реализует интерфейсы портов (в данном случае приложение использует Ef Core, базу данных Postgresql и Kafka)
  - **Presentation.Bookings** - точка входа для web-приложения, реализует эндпоинты контроллеров и фоновые сервисы.
  - **Tests.Integration.Bookings** - интеграционные тесты приложения.
  - **Tests.Unit.Bookings** - юнит-тесты с моками реальных зависимостей.

2. **Events** - в этой папке находятся проекты, относящиеся к сервису событий. Главный запускаемый проект - Presentation.Events.
  - **Application.Events** - слой приложения (use-cases для сущностей и интерфейсы портов)
  - **Domain.Events** - содержит ключевые сущности без внешних зависимостей.
  - **Infrastructure.Events** - реализует интерфейсы портов (в данном случае приложение использует Ef Core, базу данных Postgresql и Kafka)
  - **Presentation.Events** - точка входа для web-приложения, реализует эндпоинты контроллеров и фоновые сервисы.
  - **Tests.Integration.Events** - интеграционные тесты приложения.
  - **Tests.Unit.Events** - юнит-тесты с моками реальных зависимостей.

3. **Users** - в этой папке находятся проекты, относящиеся к сервису пользователей. Главный запускаемый проект - Presentation.Users.
  - **Application.Users** - слой приложения (use-cases для сущностей и интерфейсы портов)
  - **Domain.Users** - содержит ключевые сущности без внешних зависимостей.
  - **Infrastructure.Users** - реализует интерфейсы портов (в данном случае приложение использует Ef Core, базу данных Postgresql и Kafka)
  - **Presentation.Users** - точка входа для web-приложения, реализует эндпоинты контроллеров и фоновые сервисы.
  - **Tests.Integration.Users** - интеграционные тесты приложения.
  - **Tests.Unit.Users** - юнит-тесты с моками реальных зависимостей.

4. **Shared** - в этой папке находятся проекты, реализующие общий функционал, независимый от конкретного сервиса. 
  - **Shared.Entities** - общие интерфейсы для сущностей (IHasId и другие).
  - **Shared.Exceptions** - общие исключения, такие как NotFoundException.
  - **Shared.Helpers** - хэлперы для различных операций.
  - **Shared.Infrastructure.Abstract** - интерфейсы универсальных сущностей инфраструктуры.
  - **Shared.Infrastructure.Ef** - реализация инфраструктурных элементов на EF Core.
  - **Shared.Roles** - ролевая модель, общая для системы.
  - **Shared.ValidationAttributes** - дополнительные атрибуты валидации.
  - **Tests.Integration.Shared.Infrastructure** - интеграционные тесты универсальных элементов инфраструктуры.

5.  Проект **Contracts**. Здесь находятся элементы общего контракта для взаимодействующих сервисов

- Бронирование события
- Просмотр своих бронирований
- Просмотр событий
- Отмена своих бронирований

Для Администратора доступны все действия, включая создание, изменение, удаление

## Секретные ключи

На текущий момент для локального запуска можно использовать ключ в appsettings.json, если не используется docker. В production не стоит хранить ключи в файлах репозитория, необходимо использовать специальные хранилища или переменные окружения. Секретный ключ при запуске через docker-compose можно прописать в переменных окружения.

>**Обратите внимание**: ключ должен быть длиной не менее 32 символов.

## Миграции

Миграции находятся в проектах `Infrastructure.*` в папке Migrations. Управление миграциями осуществляется через EF Core фреймворк, для создания новых миграций можно выполнить из консоли диспетчера пакетов или обычной консоли соответственно команды:

`Add-Migration <Name> -StartupProject Presentation.<ServiceName> -Project Infrastructure.<ServiceName>`
`dotnet ef migrations add <Name> --project Infrastructure.<ServiceName> --startup-project Presentation.<ServiceName>`

Для выполнения миграции базы данных необходимо выполнить следующую команду или просто запустить проект:

`dotnet ef database update --project Infrastructure.<ServiceName> --startup-project Presentation.<ServiceName>`

## Фоновая обработка бронирований

Сервис использует фоновый сервис `BookingConfirmationBackgroundService` для асинхронной обработки бронирований:

1. **Создание бронирования:** При вызове `POST /events/{id}/book` создается бронирование со статусом `Pending` и возвращается ссылка на созданный объект со статусом 202.
2. **Фоновая обработка:** Фоновый сервис периодически проверяет хранилище на наличие ожидающих бронирований:
   - Событие переводится в статус Confirmed
   - Публикуется событие BookingConfirmed
   - Время обработки фиксируется в поле `ProcessedAt`
3. **Получение события сервисом Events:** после публикации события его через некоторое время из Outbox'а отправляет другой фоновый сервис `BookingEventSenderBackgroundService` в Kafka, где его читает фоновый обработчик-консюмер `BookEventBackgroundService`.
   - Если сообщение уже было обработано, то оно пропускается (проверяется в Inbox'е
   - Если событие еще не было обработано, то оно помещается в хранилище
   - Если событие не найдено, уже началось или на него не осталось мест, то логируется соответствующая ошибка
5. **Мониторинг статуса:** Клиент может отслеживать статус бронирования через `GET /bookings/{id}`

## Документация

Документация API доступна по адресу `/swagger` при запуске проекта в режиме Development. Swagger доступен в каждом проекте по отдельности.

> **Формат ошибок:** При возникновении ошибок валидации или бизнес-логики API возвращает ответ в формате [Problem Details](https://datatracker.ietf.org/doc/html/rfc7807) (RFC 7807) с соответствующим HTTP статус-кодом.

### Авторизация в Swagger

Некоторые эндпоинты требуют авторизации. В Swagger доступна кнопка `Authorize`. Для получения токена используйте логин/пароль для пользователя и вызовите `POST /auth/login` в сервисе Users. В теле ответа будет находиться токен, который необходимо вставить в форму кнопки `Authorize` для соответствующего сервиса.
