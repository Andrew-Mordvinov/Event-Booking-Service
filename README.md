# Event Booking Service

Сервис бронирования мероприятий на .NET 10 + ASP.NET Core.

## Запуск

Для запуска необходима среда исполнения для .NET 10 и база данных Postgresql (проверялось на 18 версии, но возможна работа и на более низких версиях). Для редактирования нужна Visual Studio 2026 (не ниже)

1. Клонируйте репозиторий:

`git clone https://github.com/Andrew-Mordvinov/Event-Booking-Service.git`

2. Перейдите в каталог с Presentation `/EventBookingService/Presentation` и настройте строку подключения в файле appsettings.json (ConnectionStrings):

3. Перейдите в каталог с проектом (из корня репозитория в `/EventBookingService`) и запустите команду:

`dotnet run`

или с параметрами, чтобы явно выбрать профиль http/https:

`dotnet run --launch-profile https`

`dotnet run --launch-profile http`

Сервер запустится на http://localhost:5271 и https://localhost:7240

3. Для запуска тестов можно предварительно выполнить команду:

`dotnet test`

>**Обратите внимание**: для запуска интеграционных тестов необходимо иметь установленный и запущенный Docker, так как используется пакет `Testcontainers.Postgresql`. Первый запуск тестов может быть длительным, так как потребуется загрузка образов.

## API Endpoints

### Управление мероприятиями

| Метод   | URL           |Авторизация| Описание                           |
|---------|---------------|-----------|------------------------------------|
| GET     | /events       | Да        |Возвращает список мероприятий с поддержкой фильтрации и пагинации.<br/><br/>**Параметры запроса:**<br/>- `title` (string, optional) – фильтр по названию мероприятия<br/>- `from` (datetime, optional) – фильтр по дате начала (>= from)<br/>- `to` (datetime, optional) – фильтр по дате окончания (<= to)<br/>- `page` (int, optional, default=1) – номер страницы<br/>- `pageSize` (int, optional, default=10) – размер страницы (от 1 до 100) |
| GET     | /events/{id}  | Да        | Возвращает мероприятие с указанным ID                              |
| POST    | /events       | Да (Админ)| Создает новое мероприятие. При успехе возвращает 201 Created       |
| PUT     | /events/{id}  | Да (Админ)| Полностью обновляет мероприятие с указанным ID                     |
| DELETE  | /events/{id}  | Да (Админ)| Удаляет мероприятие с указанным ID                                 |

### Управление бронированиями

| Метод   | URL            |Авторизация| Описание                               |
|---------|----------------|-----------|----------------------------------------|
| GET     | /bookings/{id} | Да        |Возвращает бронирование с указанным ID |
| DELETE  | /bookings/{id} | Да        |Отмена бронирования и возврат места    |
| POST    | /events/{id}/book | Да     |Создает бронирование на мероприятие. При успехе возвращает 202 Accepted со ссылкой на созданную бронь или 409 Conflict, если мест на мероприятие не осталось |

### Аутентификация и авторизация

| Метод   | URL            |Авторизация| Описание                               |
|---------|----------------|-----------|----------------------------------------|
| POST    | /auth/register | Нет       |Регистрация нового пользователя         |
| POST    | /auth/login    | Нет       |Авторизация пользователя и получение токена|

## Модели данных

### Event (Мероприятие)

| Поле          | Тип      | Описание                                           |
|---------------|----------|----------------------------------------------------|
| Id             | Guid     | Уникальный идентификатор мероприятия               |
| Title          | string   | Название мероприятия (обязательное поле)           |
| Description    | string   | Описание мероприятия (может быть пустым)           |
| StartAt        | DateTime | Дата и время начала мероприятия                    |
| EndAt          | DateTime | Дата и время окончания мероприятия                 |
| TotalSeats     | Int 		  | Общее число мест для мероприятия. Обязательно для заполнения                   |
| AvailableSeats | Int      | Число мест, доступных для бронировании.<br>При успешном бронировании уменьшается|

**Валидация:**
- `Title` не может быть пустым или состоять только из пробелов
- `StartAt` должна быть меньше или равна `EndAt`
- При создании через `TryCreate` выполняется дополнительная валидация обязательных полей

### Booking (Бронирование)

| Поле         | Тип               | Описание                                        |
|--------------|-------------------|--------------------------------------------|
| Id           | Guid              | Уникальный идентификатор бронирования      |
| EventId      | Guid              | Идентификатор мероприятия (внешний ключ)   |
| UserId       | Guid              | Идентификатор пользователя (внешний ключ)  |
| Status       | BookingStatus     | Статус обработки бронирования              |
| CreatedAt    | DateTime          | Дата и время создания бронирования         |
| ProcessedAt  | DateTime?         | Дата и время обработки бронирования (если выполнена) |

### BookingStatus (Статусы бронирования)

| Значение | Код  | Описание                                           |
|----------|------|----------------------------------------------------|
| Pending  | 0    | Ожидает обработки. Бронирование создано, но еще не обработано фоновым сервисом |
| Confirmed| 1    | Подтверждено. Бронирование успешно обработано      |
| Rejected | 2    | Отклонено. Бронирование не может быть выполнено    |

### User (Пользователь)

| Поле         | Тип               | Описание                                |
|--------------|-------------------|-----------------------------------------|
| Id           | Guid              | Уникальный идентификатор пользователя   |
| Login        | string            | Логин пользователя (уникальный)         |
| PasswordHash | string            | Хэш пароля                              |
| Role         | Roles             | Роль пользователя                       |

### Roles (Роли)

| Значение | Код  | Описание                                           |
|----------|------|----------------------------------------------------|
| User  | 0    | Обычный пользователь |
| Admin | 1    | Пользователь с административными правами      |

## Структура проекта

Проект разделен на 4 части (слоя) - `Domain`, `Application`, `Infrastructure`, `Presentation`. `Domain` содержит ключевые сущности без внешних зависимостей, `Application` определяет use-cases для сущностей и интерфейсы портов, `Infrastructure` реализует интерфейсы портов (в данном случае приложение использует Ef Core и базу данных Postgresql), а `Presentation` является точкой входа для web-приложения, реализует эндпоинты контроллеров и фоновые сервисы.

## Ролевая модель

Для обычного пользователя доступны:
- Бронирование события
- Просмотр своих бронирований
- Просмотр событий
- Отмена своих бронирований

Для Администратора доступны все действия, включая создание, изменение, удаление
событий, а также просмотр и отмена всех бронирований.

## Секретные ключи

На текущий момент проект исключительно учебный, поэтому ключ для шифрования JWT-токена находится в appsettings.json. В production не стоит хранить ключи в файлах репозитория, необходимо использовать специальные хранилища или переменные окружения.

>**Обратите внимание**: ключ должен быть длиной не менее 32 символов.

## Миграции

Миграции находятся в проекте `Infrastructure` в папке Migrations. Управление миграциями осуществляется через EF Core фреймворк, для создания новых миграций можно выполнить из консоли диспетчера пакетов или обычной консоли соответственно команды:

`Add-Migration <Name> -StartupProject Presentation -Project Infrastructure`
`dotnet ef migrations add <Name> --project Infrastructure --startup-project Presentation`

Для выполнения миграции базы данных необходимо выполнить следующую команду или просто запустить проект:

`dotnet ef database update --project Infrastructure --startup-project Presentation`

## Фоновая обработка бронирований

Сервис использует фоновый сервис `BookingManagerBackgroundService` для асинхронной обработки бронирований:

1. **Создание бронирования:** При вызове `POST /events/{id}/book` создается бронирование со статусом `Pending` и резервируется место,<br>если оно есть, и возвращается ссылка на созданный объект со статусом 202. Если свободных мест нет, то возвращается статус 409 и бронирование не создается.
2. **Фоновая обработка:** Фоновый сервис периодически проверяет хранилище на наличие ожидающих бронирований:
   - Если событие существует в хранилище, то бронирование переводится в статус `Confirmed`
   - Если событие не существует, то бронирование переводится в статус `Rejected`
   - Время обработки фиксируется в поле `ProcessedAt`
3. **Мониторинг статуса:** Клиент может отслеживать статус бронирования через `GET /bookings/{id}`

Защита при конкурентных изменениях обеспечивается средствами базы данных Postgresql (`FOR UPDATE` для блокировки строки в рамках транзакции).

## Документация

Документация API доступна по адресу `/swagger` при запуске проекта в режиме Development.

> **Формат ошибок:** При возникновении ошибок валидации или бизнес-логики API возвращает ответ в формате [Problem Details](https://datatracker.ietf.org/doc/html/rfc7807) (RFC 7807) с соответствующим HTTP статус-кодом.

### Авторизация в Swagger

Некоторые эндпоинты требуют авторизации. В Swagger доступна кнопка `Authorize`. Для получения токена используйте логин/пароль для пользователя и вызовите `POST /auth/login`. В теле ответа будет находиться токен, который необходимо вставить в форму кнопки `Authorize`.
